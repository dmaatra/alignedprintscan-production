# Brand and UI Guidelines

## Brand identity

- **CONFIRMED IN CODE:** The customer-facing name is “Aligned Print & Scan.”
- **CONFIRMED IN CODE:** Core positioning includes secure document, notary, print, scan, and courier-related services.
- **CONFIRMED IN CODE:** Primary services are Remote Online Notary, Mobile Notary, and Print & Scan/Document Services.
- **HISTORICAL OR POSSIBLY OUTDATED:** Some email code still says “Aligned Document Services.” New work should not copy that inconsistency without owner approval.
- **CONFIRMED IN CODE:** Logo assets exist in full and symbol forms under `assets/images/`, including WebP and original PNG variants.

## Visual language

- **CONFIRMED IN CODE:** The interface uses a navy, cream/white, and muted gold palette. Admin v3 variables include navy `#161c4d`, deep navy `#0d133c`, and related gold tokens.
- **CONFIRMED IN DOCUMENTATION:** Official Version 1 design tokens are Primary Navy `#161c4d`, Secondary Navy `#0d133c`, Dark Accent `#101744`, Primary Gold `#c8a96b`, Secondary Gold `#e8d28d`, and cream backgrounds `#f3eee4`, `#f6f3ee`, and `#f8f0d7`.
- **CONFIRMED IN DOCUMENTATION:** Primary Navy is used for primary navigation, headers, primary buttons/branding, and major titles; Secondary Navy for secondary navigation, hover/emphasis, and supporting UI; Dark Accent for footers, overlays, high-contrast areas, and admin emphasis; Primary Gold for primary accents, highlights, active indicators, and important actions; Secondary Gold for hover/decorative emphasis; cream tokens for pages, cards, sections, and forms.
- **CONFIRMED IN DOCUMENTATION:** Legacy Navy `#030431` and Legacy Gold `#d7b458` remain approved for historical assets and existing logos but are not the default colors for new UI. New UI must not introduce additional primary colors without owner approval.
- **CONFIRMED IN CODE:** Public and admin pages load Google-hosted typography and use a serif/display style for premium headings with sans-serif support text.
- **CONFIRMED IN DOCUMENTATION:** Email layouts should use white backgrounds, navy/gold accents, logo, support contact information, and avoid lavender/purple headers.
- **CONFIRMED IN CODE:** Cards, rounded pills, restrained shadows, generous spacing, and status-specific panels form the current premium UI vocabulary.

## Voice and terminology

- **CONFIRMED IN CODE:** Use “request” for customer intake/status records and “order” only where intentionally chosen for operations language.
- **CONFIRMED IN CODE:** Public navigation consistently uses “Print & Scan.”
- **CONFIRMED IN DOCUMENTATION:** Use “View Receipt,” not “Stripe Receipt”; Stripe is the processor, not the customer-facing product.
- **CONFIRMED IN DOCUMENTATION:** Prefer “priority/standard scheduling” over “rush/same-day” marketing claims, while operational same-day/next-day badges may still exist.
- **CONFIRMED IN DOCUMENTATION:** Use “Color Paper,” not “Colored Paper.”
- **CONFIRMED IN DOCUMENTATION:** Pickup by appointment is not offered for document services.

## Customer interface rules

- **CONFIRMED IN CODE:** Service-specific fields should appear only for the active service.
- **CONFIRMED IN CODE:** Multi-step intake must show progress, validate the current step, and preserve inputs while moving between steps.
- **CONFIRMED IN CODE:** Estimates must be itemized and described as estimates pending review.
- **CONFIRMED IN CODE:** Status pages use service-aware workflow labels and should show only actions valid for the current status/invoice state.
- **CONFIRMED IN DOCUMENTATION:** Final-payment and completed screens should feel settled and concise: status, service/payment summary, receipts, support, and review actions.
- **CONFIRMED IN CODE:** Print styles hide navigation/actions and keep quote/receipt content readable.

## Admin interface rules

- **CONFIRMED IN CODE:** Admin v3 uses a compact top bar, left operations navigation, persistent request rail, and right workspace.
- **CONFIRMED IN CODE:** Selected request headers and tabs remain accessible while the workspace scrolls.
- **CONFIRMED IN CODE:** Button hierarchy uses gold primary, navy primary, and outline/secondary variants.
- **CONFIRMED IN DOCUMENTATION:** Existing business functions must remain connected when presentation is reorganized.
- **CONFIRMED IN CODE:** Some admin tabs remain generated by moving legacy sections according to headings. Changes must test that every control retains its handler after DOM reorganization.

## Accessibility and responsive behavior

- **CONFIRMED IN CODE:** Forms use labels, required attributes, status live regions, and keyboard-focusable native controls.
- **CONFIRMED IN CODE:** Admin navigation has a responsive menu button and mobile/tablet behavior.
- **CONFIRMED IN CODE:** The repository includes a public accessibility statement.
- **UNKNOWN / OWNER CONFIRMATION REQUIRED:** No formal WCAG conformance audit or target level is recorded.
- **UNKNOWN / OWNER CONFIRMATION REQUIRED:** Approved browser/device support matrix and minimum viewport widths.

## Asset and content safeguards

- Official APS logo files are authoritative assets. Always reuse them; never recreate, redraw, recolor, simplify, stretch, distort, substitute, or regenerate them. Preserve aspect ratio, prefer the long logo when horizontal space permits, use the short logo when constrained, and reserve favicon/icon assets for appropriate contexts. Detailed sizing, clear-space, and placement rules may be added later.
- Use WebP assets for current page presentation unless there is a compatibility reason not to.
- Do not add processor/provider branding to primary customer calls to action unless required.
- Do not make legal, turnaround, availability, or price guarantees beyond confirmed Terms, FAQ, and current configuration.

The safeguards above are **CONFIRMED IN DOCUMENTATION** unless separately labeled as code behavior.
